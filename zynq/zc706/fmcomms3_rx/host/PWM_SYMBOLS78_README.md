# 78符号码表接收支持

## 使用

1. 重新打开RIS收端，在“PWM测速”选择“新78符号 · 配置帧…”。旧“66符号 · 10前导”入口仍保留。
2. 填写**实际每帧净荷区长度**，核对发端设定码元率。码表有78项，不代表每帧发送78个净荷；程序不会猜测该长度。默认169.971671 kBaud沿用旧实验设定，不是新信号测量。
3. 前导已按原10前导的物理波形映射为 **75 8 60 2 46 10 23 6 68 38**。发端若采用不同前导，须填写实际序列。
4. 预览并“另存新JSON”，再“明确应用到当前分析”。应用后清除旧BIN及绑定参数，选择本次新采样与对应.bin.json，确认发送配置后运行。自动搜索完成后回放完整文件，最长2秒。
5. 没有真实净荷参考时保持BER关闭。若已确认真实发端参考，在向导填入实际新表编号序列并启用；不会把0～77自动作为真实发送数据。

普通帧向导的“实际码表”页新增“导入MT文本（高电平%,时延%）”。格式严格为每行 `(高电平百分比,时延百分比);`。内部码表是“时延片数 高电平片数”，两者列序和单位不同。导入保持文件行序，按原物理波形重映射前导，清空旧净荷长度、参考、循环校准；缺失前导波形或格式错误时不改变草稿。

## 本次码表

- 原附件mt_test_plus.txt，78项，编号0～77；每周期20片，每片5%。
- 最小高电平5片；延迟+高电平最多16片，末尾低电平最少4片(20%)。原66项均保留，新增12项位于16片边界。不能继续使用原5片低电平限制。
- 行序从延迟0/高5～16片开始，延迟每次增加1片，最后一行为延迟11片/高5片。
- 原66表插入新行后部分索引改变，不能把旧前导、净荷参考或校准编号直接照搬。
- 78态每符号等效容量上限log2(78)=6.285402219 bit；7位输出只是编号标签。BER是按这些编号标签与实际参考比较，实际信息比特映射/纠错未定义时不能称真实数据比特吞吐。
- 新边界码字低电平余量较小，器件拖尾、噪声和采样率会影响可分辨性。合成结果不能保证实测性能。

## 命令行创建配置

`rx706_pwm_symbols.py` 要求显式传入 `--payload-symbols`、`--symbol-khz` 和不存在的 `--output` JSON路径。不会自动启用净荷参考，不覆盖旧文件。生成的schema3 JSON可直接载入原接收GUI与自动搜索CLI。

## 文件和验证边界

- mt_test_plus.txt：原上传文件，SHA256 7ed5818a505b4fb052dca969cdd461c0bbfd3338c13ffa2e4440544c261b02e7。
- codebook_78.csv：逐行编号、百分比、片数和末尾低片。
- preamble10_remap.csv：原10前导编号到新编号的一一波形映射。
- tests/test_pwm_symbols78.py：导入、非法输入、波形映射、78种解码、编号BER、擦除与拖尾边界。
- tests/test_pwm_symbols78_gui.py：真实Tk入口、取消、失败、保存/重载、66切回及工作中保护。
- tests/verify_pwm_symbols78_iq.py：合成int16 IQ经生产接收链和自动搜索，完整2秒，另测反极性短片段；生成报告明确标为合成，不是用户实采。

没有本次新码表的真实采样或发端净荷记录，不能认证实测BER。旧66的JSON与用户BIN未改动。

## 本次实跑结果

105项回归全部通过，包括新78码表、真实Tk流程、旧66、自动搜索和2秒读取边界。完整2秒合成IQ实跑15.36 MS/s、30,720,000采样；先在1秒内选参，再独立回放完整2秒，覆盖301,314个完整净荷符号，共比较2,109,198个编号标签位，BER=0、擦除=0。恢复码元率169,974.220580 Baud，发送合成时钟为旧设定+15 ppm。另测反物理极性短片段通过，未启用参考时BER为null。

详见frame_profiles/symbols_plus_78/synthetic_iq_validation.json。测试净荷0～77仅为合成验收夹具，未写入用户默认配置。以上不能替代新码表实采验收。
