# 64QAM 接收模式与验证

64QAM 与 256QAM 共用接收流程；在“QAM阶数”选择 64。默认仍是 256，原有配置/冻结方案仍按保存的阶数复算。发端码本脚本未改动。

## 映射、幅度和 HEX

发端 `ris_codebook_gui.py` 的 64QAM 标签为 0～63，六位 `IIIQQQ`，高三位 I、低三位 Q，分别 Gray 解码后得到电平 −7、−5、−3、−1、1、3、5、7。四角按左下→左上→右上→右下排列时是 `00 04 24 20`；256QAM 仍为 `00 08 88 80`。当前64QAM发送帧已由用户确认为三段PWM后连续发送这组四角两遍，再发送128个物理净荷符号，整帧循环。

发端以最大角点归一化 `(I+jQ)/(7*sqrt(2))`，接收端以平均功率归一化 `(I+jQ)/sqrt(42)`；公共复增益标定吸收两者的整体比例，不能把它误认为 64QAM 映射差异。对于分布很稀疏的载荷，盲 RMS 增益本身仍可能有偏差，应使用实际发送的训练或已知校准。

显示/CSV 的每个 HEX 值为两位 `00`～`3F`，高两位始终为零；每行候选比特为六位。两位 HEX 是一个符号 id 的存储表示，不是每符号八个净荷 bit，也没有按六位跨符号打包为字节流。训练 HEX 和净荷 HEX 分开显示/导出。没有发端净荷参考时 BER 未测。

## 模式覆盖

| 原有模式/功能 | 64QAM | 条件与边界 |
|---|---|---|
| 普通直接 I/Q QAM：矩形/RRC、盲定时/静态相位 | 支持 | 已知 Fs、符号率、载波、成形；存在 90° 歧义 |
| 普通 QAM：可配置已知训练、固定残余频偏/增益 | 支持 | HEX/十进制/二进制/IQ 奇数电平；不自动去除后续重复前导 |
| PWM 前导 + 普通 QAM，有/无 QAM 训练 | 支持 | 按真实 PWM 序列/频率/片数填写；PWM 不能确定 QAM 绝对映射 |
| TDCM 谐波：原接收、PWM/盲归一化 | 支持 | 标称谐波基频与符号率之比须为正整数；±1 谐波测试覆盖 |
| TDCM 手动/重复时钟、公共相位、定时和幅相补偿 | 支持 | 同原流程；平方/均值参考不是逐符号消相位 |
| TDCM 已知训练、逐帧幅相/复零点/镜像校正 | 支持 | 必须发送非退化且顺序正确的训练；训练剔除、坏帧拒绝 |
| 3PWM + 四角训练专用预设 | 支持 | 按当前阶数选择四角；64QAM 需明确填写实际每帧净荷数 |
| 有前导自动补偿组合搜索 | 支持 | 指定真实总窗口候选（包含训练），重复结构和独立后段验证 |
| 无前导重复图样，手动/自动搜索 | 支持 | 需两态载波参考、标称速率/谐波和重复图样；无协议帧起点证明 |
| 无前导固定时钟/随机载荷 | 支持 | 须给出真实时钟或手动 ppm；随机载荷不自动估计钟差 |
| 补偿前后图、逐帧/逐块、判决边界、HEX、CSV/HTML | 支持 | 图为实际复系数，不吸附格点；导出自包含 HTML |
| 自动方案 JSON / 无前导配置 JSON 导出与复算 | 支持 | 保存阶数及有效位数，同一输入指纹保护，原 256 方案兼容 |

普通 QAM 的镜像/复零点训练校准，以及无前导入口的已知 QAM 训练，目前与 256QAM 一样不支持，调用时明确拒绝。镜像/复零点训练用于有前导 TDCM 路径。普通 QAM 的至少 256 个观察符号是公共统计窗口要求，不表示一个帧固定为 256 符号，也不表示 64QAM 仍使用八位标签。

## 当前64QAM帧：3+4+4+128

用户最新确认：`3个PWM → 00 04 24 20 → 00 04 24 20 → 128个物理净荷符号`，整帧循环。128个物理符号按相邻对重复，例如 `01 01 02 02`，对应64个逻辑位置；不能据此假定真实净荷内容恰好是0～63顺序扫描。

默认无额外尾部时，每帧QAM提取窗口为 `8+128=136`，加前3个PWM为139个周期（PWM与物理符号同速时）。前8个训练符号独立校准并剔除，物理净荷128个全部保留。新增“64QAM：3PWM＋双遍四角＋成对净荷”模式/补偿页“64QAM当前帧：3+4+4+128”按钮，启用按帧重复时钟、公共相位跟踪和已知训练。

```sh
/opt/anaconda3/bin/python3 /Users/carrot29/work/code/ris/rx_code/zynq/zc706/fmcomms3_rx/host/rx706_gui.py --paired-64-frame
```

此命令选择64阶、双遍训练、128物理净荷和连续重复数2，不自动连接、不自动分析文件；Fs、载波、PWM频率、基频和物理符号率仍须核对。主窗口“IQ信号分析…”或新模式入口均可使用。`--qam-order 64`/`--qam-order 256`仍可只设置本地分析默认阶数。

结果的“候选符号/比特”及物理CSV保留全部物理判决；“重复对 / 帧尾 / CRC”页和独立重复对CSV列出64个逻辑位置。只有两次判决一致且逐帧边界有效时，才填一致逻辑候选；不一致显示`?`/空值，保留两次HEX和实际复系数，不平均、不投票、不自动改写为64符号流。重复一致率不是BER或净荷准确率。

旧单遍四角、无前导、普通QAM和256QAM模式保留。通用四角预设可填写物理净荷数、训练遍数1/2、净荷连续重复数1/2；单遍64QAM四角仍是`00 04 24 20`，256QAM仍是`00 08 88 80`。通用命令 `--four-corner-training --qam-order 64 --payload-symbols N` 保留为单遍配置，N须明确填写；`--paired-64-frame`与它互斥，专用于当前128物理净荷帧。

## 额外尾部与CRC预留开关

CRC算法、多项式、初值、异或值、反射方式、打包、字节序和校验范围都未确认。用户明确要求先保留功能入口，不尝试反推；**不将提到的A6548AB7当作算法参数、结果或加密方式，不计算CRC，也不标通过/失败**。

GUI“CRC / TDCM帧尾调试”默认关闭，可用 `--crc-debug` 打开；无参数时报告`unverified/未验证`。这只是调试入口，不是已经配置好的CRC计算器。原始IQ和物理判决始终保留。

“每帧额外尾符号数”/`--tail-symbols`默认0，只能在观察到额外符号后手动配置，不自动猜CRC长度。设为T后，当前模式提取`136+T`个QAM窗口（完整帧`139+T`周期，等速时），前128个净荷仍组成64重复对，其余T个单独显示/导出为“未分类额外尾符号”，并保留在物理CSV。若真实帧尾存在额外符号而配置仍为0，同步可能失败；不能据此判CRC失败。未验证逐帧边界时不生成伪逻辑候选。

## 已检查的实际码本和数据证据

只读检查了 `码本/ris_64qam_codebook.zip` 和 `码本/ris_64qam_64slice_codebook.zip`：各含 64 点、400 单元、L=16/64、PWM=160 kHz、K=1，元数据标称 Rs=160 kSym/s、裸比特率=960 kbit/s。这些数值来自码本，不是 IQ 采样率或接收实测速率。若实际使用这些码本，TDCM 标称基频为 160 kHz、K=1 时符号率也为 160 kSym/s；Fs 和载波位置仍按采集参数填写。

核对了全部 `IIIQQQ`、HEX、二进制驱动状态、width/start 和 ZIP 校验和；从实际驱动状态独立重建了文档中的传播/谐波模型。模型公共增益消除后的参考 EVM 分别为约 5.4112% 和 1.0673%，与码本元数据一致；在假设四角标定的模型对照中 64 点判决均正确。此为模型验证，**不是实测 IQ 或空口 BER**。

ZIP 是每个符号的驱动查找表，没有 PWM 前导、四角发送顺序、帧长或载荷序列。当前3+4+4+128结构来自用户明确确认，不是从ZIP推断。已找到真实候选文件 `/Users/carrot29/work/code/ris/数据/rx_64qam_64slices_160k.bin`，122880000字节，无同名采集JSON。按手动Fs=15.36MSPS、160kSym/s和用户确认帧结构的首次只读测试未通过PWM/已知训练同步，尚未可靠恢复星座；不报告净荷准确率或BER。文件名和码本参数不能替代采集元数据，实际窗口交互仍未验收。
