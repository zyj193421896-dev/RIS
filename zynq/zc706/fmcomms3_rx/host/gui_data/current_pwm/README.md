本目录是 GUI 的固定 PWM 数据目录，不依赖启动时的工作目录。

主窗口默认把新下载保存到本目录，文件名自动生成为 rx_时间戳.bin，配套元数据为同名.bin.json，避免覆盖已有采样。

打开“接收信号分析”，点击文件栏中的“加载固定 PWM 数据”，再点“分析信号”。按钮同时加载 frame.json 和本目录中最新修改的 rx_*.bin（初始只有rx_test.bin），设置 RX1、15.36 MS/s、起点0、恢复时长1秒、B=1、抽取1。状态栏显示实际选中的文件名。不会自动连接板卡或开始采集。frame.json仍需与实际发端帧结构一致，换发端前导后请同步更换它。

- rx_test.bin：从项目 captures/rx_test.bin 复制的实际1秒IQ采样。
- rx_test.bin.json：配套采集元数据。
- capture_manifest.json：复制后的长度和SHA-256，已核对与源文件一致。
- frame.json：当前默认的循环4点校准配置，保留4个25%身份码定位，将原净荷序号3～6的40%、45%、50%、55%已知脉冲指定为校准前导，跨64个循环取中位数；这些位置不计入BER。169.971671 kHz，单用户、码表66种，默认左右区间判决。原名frame_cycle_middle4.json，现直接由快速加载按钮使用。
- frame_original.json：严格要求4个前导都符合的原配置，identity_errors=0，便于同参数回归。原 host/frame_profiles 配置保留。
- frame_mixed_preamble.json：供修改发端、重新采集后使用的配置。4个前导改为符号0、5、0、5，即(宽度25%,延迟0%)、(50%,0%)、(25%,0%)、(50%,0%)，之后净荷仍为0～65。不能用于已有 rx_test.bin。
- frame_xiangxiabu.json：保留用户当前保存的另一份配置；以文件实际字段为准，文件名不会自动改变判决方式。

旧录制文件的4个相同脉宽前导只能估计单点宽度偏置，无法识别脉宽增益；接收机不会用已知净荷偷偷标定。新混合前导覆盖两种重复脉宽，可估计脉宽增益和偏置。实际器件若仍有非线性或状态相关响应，需要增加标定宽度或调整模型；不能保证仅靠更换前导就得到零误码。

当前速率按用户指定的码元口径：log2(66)×169971.671 ≈ 1.027376 Mbps，前导也按码元计入。它与正确净荷吞吐率分开。

以后可将新的配套采样和配置放在这里；采样使用rx_*.bin及同名.bin.json，配置使用frame.json。GUI快速加载不修改文件内容。
