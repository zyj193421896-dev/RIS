# 256QAM：120 kHz、64 slice、3+4+16明文

## 当前发收约定

- 256QAM，Gray标签 `IIIIQQQQ`，每个物理符号8 bit。
- PWM基频120 kHz；每symbol恰好1个PWM周期（K=1），符号率120 kSym/s，周期8.333333 µs。
- 每周期64片，片宽130.208333 ns，片速率7.68 MHz。
- 3个相同PWM前导，各64片：16片高、48片低，25%占空比。三个完整周期共25 µs。
- 单遍四角训练：`00 08 88 80`，4个符号。
- 16个物理明文符号。训练加明文为20个QAM窗口，整帧23周期，191.666667 µs；无额外尾部、无切换间隔。
- **当前帧明确没有CRC。** 不期待、提取或校验CRC，不自动补尾字节。128个ADC采样点/符号不是128个净荷符号。
- 16个明文符号均按8-bit物理值保留，不合并、不假定重复；未约定文本编码，不把HEX标签擅自解释成ASCII或其他文本。

## 通用参数JSON

如GUI已在运行，请重启以加载新的导入代码。在IQ分析窗口的“QAM 补偿（64 / 256）”页，点击“载入参数 / 冻结方案 JSON…”，选择此文件。

此JSON使用 `version=1, method=tdcm_parameter_config`，不含IQ路径、数据指纹、采样率、原载波、通道或起点。加载后这些采集选择保持不变，也不会自动分析；请核对当前Fs与原载波，选择实际IQ文件，再点击“分析信号”。加载使用通用“TDCM 谐波QAM”模式，参数与上述3+4+16约定一致。不要再点击其他预设覆盖这些参数。

参数JSON不是冻结标定结果，可以用于不同IQ文件。采样率相关条件在分析时按实际Fs检查。现有冻结方案仍保留同文件指纹保护。本次27项针对性无GUI回归通过，包括同一JSON加载到两份不同合成IQ、捕获选择保持不变、禁止自动分析、无CRC，以及旧模式/冻结入口兼容。

## 启动

在 `fmcomms3_rx` 目录运行：

```sh
/opt/anaconda3/bin/python3 host/rx706_gui.py --qam256-120k-frame
```

此命令现在选择“256QAM：120k／64片／3+4+16”，只预置本地分析参数，不连接板卡，不自动打开或分析文件。也可在分析窗口的“星座处理”选择该模式。这个入口不再使用旧3+8+128帧。

按实际采集填写Fs和原载波相对RX LO的有符号基带频率，手动选新IQ文件分析。预设保留当前Fs与原载波值，不能把默认值当成实测值。+1谐波位于原载波+120 kHz，原载波框不能填写这个边带频率；如实际用-1阶须手动修改目标谐波。

当前预设关闭整帧重复时钟搜索和全记录公共相位跟踪，按已知标称周期分帧，各帧使用自己的4个真实四角训练校准。因此净荷可逐帧变化，单个短帧也可分析。若存在采样时钟偏差，可设置已知手动ppm；不能未经证实改成重复图样模式。

Fs=15.36 MSPS时每周期128个ADC点、每片2点，高/低前导平台分别32/96点。已知前导允许至少2点/片，并保留连续平台至少3点、两态拟合和频偏检查。固定16+48前导无可调数据区；这不放宽独立PWM v2解调要求。

数据段的64片是发端开关码本，收端TDCM按完整符号窗口提取目标谐波，不逐片判决。不要用普通直接I/Q“QAM解调”替代，也不要重新点旧通用四角配置覆盖成25/5/8前导。
