# PWM 同步与标定修复（2026-11-09）

## 范围

本次修改针对 Mac 工作区的 PWM 解调，不是 Windows 原电脑的状态判断。Windows `rx_test.bin` 历史报告只能作为问题背景；本次实际复放文件为 `数据/super_pwm/rx_pwm_4pliot_66symbol_170khz.bin`，结果另存相邻 `analysis_20261109`。原IQ和原 `single_user_mt_test_169971.json` 保留。

## 接收机改动

- 前导初捕获采用重复中位数估计局部斜率，允许明确计数的单个边沿异常。
- 时钟跟踪使用多前导间隔的稳健斜率，不再让一次短间隔偏移直接改变整个后续符号时钟。
- 最终长基线周期确定后，重新以该周期对已知前导的发送延迟做稳健相位估计，并重新计算标定。
- 相邻前导候选都成立时，显式标记 `ambiguous`。已有未失锁时钟可提供跟踪依据；失锁后不能借旧可信状态假装锁定。歧义和缺失净荷保留时隙、按擦除统计，不能当作正确判决。
- CSV/行记录增加 `sync_status` 和 `calibration_model`；前导记录包含异常边沿计数、宽度比例与偏置、模型是否可辨识。
- 单一已知脉宽只能支持 `offset_only`；宽度增益未知。多种已知脉宽且足够有效前导时，使用稳健仿射宽度模型。参数全部来自前导，未读取净荷参考。
- 参考序列仅在冻结判决后计算误码。没有参考重排、答案替换、固定1.72us或硬编码实测宽度拟合系数。

## 新实验前导

另存 `frame_profiles/limit15_step5/experimental_mixed_preamble_169971.json` 与对应 `_tx_percent.txt`。身份码字为 `0 5 45 2`，对应发端(宽度%,延迟%)为 `(25,0), (50,0), (25,25), (35,0)`，后接净荷0～65，仍为70项。它提供多宽度和不同时延信息，收端支持相应标定。

这是需要发端重新发送、重新采集的实验方案，不适用于现有四个0前导的旧IQ，不代表硬件验证完成。

## 验证边界

四个相同前导与首净荷相同，仍可能无法唯一定位；只有一个已知宽度也不能证明宽度增益。扩大擦除是如实报告不确定性，不能被宣传为解调性能改善。BER必须与擦除、身份失败及BLER一起报告。

66码字的7位编号只用于显示与参考比较，不等同7bit信息量；信息量为log2(66)，用户速率计算考虑前导和多用户时隙。

专项测试覆盖五连相同脉冲、异常首边沿、最终周期相位一致、竞争候选与漏检重捕获、单点不可辨识与多点标定、参考变化判决不变、多用户与旧配置保留。portable测试独立进程运行。
