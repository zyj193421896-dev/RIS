# 用户身份前导、时延/脉宽联合调制及前导拖尾校正

2026-11-08：默认PWM（占空比）循环发送 `U1前导|U1净荷|U2前导|U2净荷|…`，没有缓冲和公共训练。用户数默认1，可配置1～16。每个用户的前导序列、前导长度、数据长度及已知数据均可编辑。默认每个前导16符号、净荷1024符号。前导之前的采集残片不输出确认净荷；首前导搜索范围可配置，0表示整个恢复范围。

## 片数与下降沿拖尾

占空比网格从0起：`N=100/步长百分点`，5%对应20片，4%对应25片。起始占空比输入已删除。一个码字是 `(d,w)`：前置低电平d片，高电平w片，其余为低电平。d允许大于0；w最少6片，可配置。当前处理符号内单个高脉冲，不支持循环回卷的脉冲；跨周期拖尾导致脉冲粘连时记擦除。

拖尾完全由各用户身份前导估计，没有固定拖尾值、初始值或围绕某个固定值的搜索范围。每个已知前导给出实际接收高脉冲时长和发端已知脉宽，两者差值的稳健统计量作为本次下降沿拖尾；同时检查前导边沿/宽度残差。它校正的是发端拉低后收端仍保持高电平的时间，不是整体IQ时移：

```
原始高脉冲 = 接收下降沿 - 接收上升沿
校正高脉冲 = 原始高脉冲 - 本次前导估计拖尾
脉冲延迟   = 接收上升沿 - 已恢复的符号边界
```

符号边界由已知前导恢复；多个前导的长间隔用于提高符号周期估计精度。不将数据相关的上升沿强制当成符号边界。

短前导处理：寻找下一个前导前，使用配置的符号率外推时隙；取得多个前导后再用长间隔拟合周期。只有一个完整前导时继续采用配置周期，避免用4个符号的局部抖动斜率外推长净荷。前导边沿/宽度容差另外计入一个实际处理采样周期的测宽余量（上升/下降沿各半个采样周期）。这不扩大用户身份容错数量，也不使用净荷参考帮助匹配。

## 合法组合、码表及信息率

默认启用联合码表，自动枚举合法整片组合：

```
L = 发端末尾低电平预留（默认1片，可配置）
d ≥ 0，w ≥ w_min，d+w+L ≤ N
A = N-L-w_min+1
全部合法组合数 = A(A+1)/2（A>0）
```

时延和脉宽不能同时最大。码字按d从0递增，同一d下w从最小值递增编号。默认5%、最小6片、末尾低电平预留1片时，N=20、M=105。码字0～13为`(0,6)`～`(0,19)`，码字14起为`(1,6)`、`(1,7)`…，最后为`(13,6)`。

点击“查看 / 编辑延迟与脉宽码表”，每行填写`延迟片数 高电平片数`，对应符号0、1…；可以使用全部组合或自定义子集。改变步长、最小宽度或发端低电平预留后，自动码表和编号可能改变，发收端必须同步配置。实测拖尾不会自动修改码表或编号。取消联合码表可只按补偿后的脉宽识别符号，此时数据延迟单独恢复，不参与符号映射；需配置有效脉宽档数，同宽码字不能重复。

界面自动计算，M指实际选用的码表大小：

```
每符号信息量上限 H = log2(M)
一轮周期数 C = Σ(用户前导长度 + 用户净荷长度)
用户u净荷信息率上限 Ru = 符号率 × 用户u净荷长度 / C × H
```

默认105种对应6.714246bit/符号。速率只显示含前导、含用户时分开销的单用户净荷信息率，不单列无帧开销速率。三个等长用户均分时隙，不同长度按实际占比计算。这是状态信息量及理论净荷信息率上限，不是实测正确吞吐率。

M不是2的整数次幂时，逐符号固定整数比特映射最多取`floor(log2(M))`位，需选2的整数次幂个码字；充分利用全部状态需跨符号映射。当前输出用`ceil(log2(M))`位表示符号编号，默认7位但只有105种有效，不能当作7个独立净荷比特。已知数据BER按这一明确的编号映射比较。

## 周期下限估计

采集前只显示当前周期和最短发端高电平时长，周期下限显示待前导估计。采集后用各前导实测拖尾评估高电平稳定条件，并在逐块JSON记录要求拖尾完全结束在本符号内的保守周期下限。稳定条件来自当前器件观察，仍需实测，不会凭估计自动改变发端参数。

前导估计出的拖尾也用于统计当前码表中有多少码字可在预留低电平后仍将拖尾完整留在本符号内。该数是保守可用性评估，发送码表的编号保持不变。实测拖尾可能跨过符号边界；只要两个边沿仍能独立观察，就测量并补偿。若与后续脉冲粘连、边沿丢失或前导残差过大，则记擦除，不能用参考数据补位。界面不会把理想组合数或理论速率宣称为所有组合已实测可用。

## 前导、误码与导出

2026-11-09：数据符号默认采用最近码字判决。已定位前导且高脉冲结构完整时，使用补偿后的脉宽和延迟共同寻找最近码字；超过默认0.4片容差仍显示符号及其比特，并标记“最近码字估计；超容差”。等距时按码表顺序选择并标注估计。容差用于区分估计判决与档内判决，不再仅因超差输出问号；前导匹配仍使用原来的严格残差检查。

最近估计在符号表以金色及“估计判决=是”显示，CSV包含估计标记和最近码字距离。它们按实际判决正常参与BER/误块率，错误仍计为错误；不使用已知参考挑选码字或回填结果。缺少唯一完整脉冲、补偿宽度无效或用户身份失败时，仍保留擦除。脚本调用可用`nearest_decision=False`恢复严格容差拒绝行为。

默认前三个用户的16符号前导：

| 用户 | 前导序列 |
| --- | --- |
| U1 | `0 0 0 7 7 0 7 7 7 7 0 0 0 0 7 7` |
| U2 | `7 7 0 0 0 0 7 7 7 7 0 0 0 7 7 0` |
| U3 | `7 7 7 0 0 7 0 0 7 0 7 0 7 7 0 0` |

这些是码表中的符号编号，不是0%/100%。默认0为延迟0/宽6片（30%），7为延迟0/宽13片（65%）。自定义码表后，前导必须对应发端实际码字；应避免重复、过短及容易相互混淆的序列。

每个已知身份前导估计时钟相位和下降沿拖尾，并检查边沿/宽度残差。坏前导保留原时隙，其净荷按擦除输出，后续用户不会向前滑动。净荷参考不用于同步、校准、极性选择或纠错。

用户配置中可填写已知符号、二进制编号序列或载入UTF-8文本文件。可选循环参考、每块重置或按用户连续消耗参考。坏块也消耗原位置，不搜索最佳参考相位。空参考表示未测。

- BER：错比特数/已判决且有参考的比特数，擦除位数单列。
- BLER：出现错比特、擦除或身份失败的完整块数/参考完整覆盖的块数。
- 尾部残块、参考未覆盖块单列；没有分母时显示未测。

表格/CSV含用户、块号、原始高脉冲、补偿后宽度、脉冲延迟、上升/下降沿、估计拖尾和前导残差。可按用户筛选并导出净荷比特流。逐块JSON包含码表、理论信息率、各前导校准结果和整体/逐用户指标。

`pwm_frame_single_user.json`和`pwm_frame_three_users.json`已更新为新规则。旧快速预设仍可测试原有单用户文件；旧算法保留供脚本调用。
