# 可选新采集前导模板（2026-11-10）

此文件是改善前导的建议，不是自动选择结果。最终前导由用户确定，每次采集使用固定组合。没有修改当前 `host/gui_data/current_pwm/frame.json`，没有改发射端。

## 必须先确认发端，再重新采集

GUI 可加载 `frame_new_capture_preamble12.json`。**它不能用于旧的“4个0 + 66符号”IQ文件。** 发端必须确实发送以下固定帧，且一符号就是一个完整PWM周期：

`0 65 8 54 2 42 10 21 6 60 4 35`，随后66个净荷符号，然后重复。

本模板不指定净荷实际内容。默认 `reference_enabled=false`、`reference=""`，因此不应输出有意义的BER。只有确认发端66个净荷确实为 `0 1 ... 65` 后，才将该串填入reference并启用参考；其他固定实验组合须填其真实序列。不能用接收结果生成参考来“降低BER”。

**今天要测1秒数据的真实BER，除了前导，还必须由用户提供实际发送的净荷参考和对应映射；只知道前导不足以计算真实BER。** 附带 `fixture_ONLY_IF_TX_payload_0_to_65_new_capture.json` 仅供明确采用“上述12前导 + 0..65净荷循环”的实验：它启用0..65参考，不自动应用，不能代替发端确认，也不能用于旧IQ。主JSON仍保持无参考。

`cycle_calibration={}`：12个身份前导同时用于符号时钟、相位和脉宽gain/offset拟合，不从净荷借用校准槽。66个净荷位置全部保留。原配置的payload_indices 3..6只是明确保留的已知循环校准槽，并不是替代4个0的物理帧首。

## 选择依据及局限

12符号是开销与稳健性间的工程折中，不声称全局最优。覆盖7种延迟和8种宽度，宽度5..15片覆盖现有码表全宽区间，可独立估计线性gain与offset；宽度重复与非重复穿插，延迟大跨度非周期排列，避免全0前导的相位模糊。与仓库现有 `0 5 0 5` 相比，不采用短二符号重复结构。14/15片宽度若发生非线性边沿提前，线性拟合仍可能有偏；真实硬件必须验收。

对于明确的“本12前导+0..65”循环，77个非零循环起点与目标12符号的最小Hamming距离为10；生产 `_header` 在无噪声及所测噪声下没有错误起点匹配。这不等于对任意净荷证明唯一：任意不受限制净荷可原样包含这12符号，甚至包含一个完整假帧。严格保证需要约束净荷/转义、带外分隔或额外帧校验；本模板没有新增这些协议机制。

## 可复现验证

运行（从 `zynq/zc706/fmcomms3_rx`）：

`PYTHONDONTWRITEBYTECODE=1 /opt/anaconda3/bin/python -m unittest discover -s tests -p test_pwm_preamble12.py -v`

3项通过：采用GUI的schema转换后生产验证器接受；30组循环起点/边沿噪声测试仅正确起点；8种gain/offset/初相/固定或随机净荷组合完整解码。参考禁用，校准不使用净荷。

`PYTHONDONTWRITEBYTECODE=1 /opt/anaconda3/bin/python host/frame_profiles/new_capture_preamble12_20261110/audit_preamble12.py`

追加审计：gain=1.05/1.08/1.11，offset=-0.018/0.069/0.156µs，10个随机种子，每组3帧；每个噪声档90条数据。抖动模型为每个上升/下降边沿独立零均值高斯，σ不是最大误差。固定容差0.4片、采样率15.36MHz；nearest判决。

验收须记录发端真实组合、约1秒新IQ、当前文件实测码速率，以及在真实已知净荷参考下计算的BER/擦除/完整帧数；前导正确捕获不能代替BER验收。
